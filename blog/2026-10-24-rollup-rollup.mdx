## Codemod / Tooling Files in Results

The five top-ranked functions are all in generated _expected.js fixtures under test/form/samples, which hold bundled output of third-party libraries (core-js, es6-shim, es5-shim) used as test expectations. They score highly because inlining a whole library into one wrapper function produces very high path counts and fan-out. To keep them out of the ranking, add `{ "exclude": ["test/form/samples/**/_expected.js"] }` to .hotspotsrc.json.

First, a framing note. Every one of the top five is in a file named _expected.js under test/form/samples. By its name and location, that file holds the expected output of a bundling test case, which suggests these functions are the result of rollup bundling third-party code (core-js, es6-shim, es5-shim) and not hand-written rollup logic. The excerpts support this: they show the wrapped, lazily-initialized `require...` shape that a bundler produces when it inlines CommonJS modules. None of the five has been touched in the last year, and all were last changed 56 days ago.

That has a practical consequence. These scores say a lot about the complexity of the inlined libraries and very little about the maintainability of rollup itself, so I would not schedule refactoring work against them. I still describe what the metrics show below, because the same numbers would be alarming in code a team owned.
