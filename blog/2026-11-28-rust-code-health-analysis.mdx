Rust developers often assume that the language's strict compiler and ownership semantics naturally lead to cleaner code. The data tells a different story. Across 69 open-source Rust repositories, we found that 87% contain functions too large to reason about as a unit, and 78% have god functions—code that combines high complexity, excessive fan-out, and length simultaneously. The borrow checker enforces memory safety, not architectural discipline.

## Methodology

We computed an activity risk score for each function by multiplying structural complexity (cyclomatic complexity × nesting depth × fan-out) by recent commit frequency. Functions that are both complex and actively changing score highest, since they represent the most urgent maintenance burden. We analyzed 69 Rust repositories over a trailing git history window, identifying functions that exceeded established thresholds for each antipattern category.

## The Most Common Antipatterns

Long functions appeared in 60 of 69 repositories (87%). Rust's expressive type system and pattern matching encourage inline handling of variants, which frequently leads to functions that grow beyond reasonable bounds. A single `match` statement covering an enum with twenty variants can easily push a function past 100 lines.

Exit-heavy functions showed up in 59 of 69 repositories (86%). Rust's `Result` type and the `?` operator make early returns idiomatic, but this same pattern can scatter responsibility across dozens of exit points within a single function. What starts as ergonomic error handling becomes a maze of potential termination sites.

Complex branching affected 58 of 69 repositories (84%). Pattern matching, combined with `if let` chains and nested conditionals for error handling, drives cyclomatic complexity above the refactoring threshold of 15. The language makes branching easy to write, but that ease doesn't come with guardrails.

## The Highest-Risk Repositories

[nushell/nushell](/blog/2026-08-20-nushell-nushell/) tops the list with a risk score of 37.1. The shell's parser and command dispatch logic exhibit all three structural antipatterns simultaneously: complex branching, deep nesting, and god functions. Shell languages require handling many input variations, but the concentration of that logic into single functions creates maintenance hazards.

[rust-lang/cargo](/blog/2026-09-26-rust-lang-cargo/) scores 26.6, driven by long functions, exit-heavy code, and god functions in its dependency resolution and build orchestration paths. As the official Rust package manager, Cargo handles significant edge cases, but several core functions have grown past the point where any single developer can hold them in working memory.

[servo/servo](/blog/2026-08-23-servo-servo/) registers a risk score of 21.1. The browser engine contains long functions and complex branching throughout its layout and rendering code. Browser engines are inherently complex, but the concentration of that complexity into god functions increases defect probability.

[rust-lang/rust-clippy](/blog/2026-09-11-rust-lang-rust-clippy/) scores 21.0. The linter's pattern-matching logic for detecting antipatterns ironically exhibits exit-heavy and complex branching patterns itself. Each lint check handles numerous AST node variations, often within single functions.

[bevyengine/bevy](/blog/2026-08-17-bevyengine-bevy/) rounds out the top five at 20.3. The game engine's ECS architecture and rendering pipeline show complex branching and god functions in system scheduling and asset loading code.

## What This Means for Rust Developers

Rust's compiler catches memory errors, type mismatches, and data races. It does not catch architectural decay. The prevalence of long functions and god functions across 78% of analyzed repositories demonstrates that structural code health requires explicit attention regardless of language.

The exit-heavy pattern deserves particular scrutiny in Rust codebases. The `?` operator and early-return idioms are powerful tools, but they can mask growing function complexity. When a function has more than a handful of exit points, it becomes difficult to reason about postconditions and resource cleanup, even with RAII. Consider whether functions with many early returns should be decomposed into smaller units with clearer single responsibilities.

## Analyze Your Own Repository

You can run the same analysis on your local Rust projects. Install the CLI:

```bash
brew install Stephen-Collins-tech/tap/hotspots
```

Or on any platform with Cargo:

```bash
cargo install hotspots-cli
```

Then run the analysis:

```bash
hotspots analyze .
```

The tool will identify your highest-risk functions and the specific antipatterns driving their scores.
