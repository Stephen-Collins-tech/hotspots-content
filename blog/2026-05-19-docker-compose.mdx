Based on its name and location in monitor.go, this function likely drives the core monitoring loop for running Compose services. A cyclomatic complexity of 16 means there are at least 16 independent execution paths to reason about and test; a max nesting depth of 5 pushes into the range where control flow becomes genuinely hard to trace; and a fan-out of 17 means changes here can ripple to 17 distinct callees. The combination of god-function, deeply-nested, exit-heavy, and long-function antipatterns signals that this function has accumulated responsibilities that belong in separate, narrower units — making every live edit a high-stakes operation.

**Recommendation:** Before the next feature lands in monitor.go, add characterization tests that exercise each of the 16 cyclomatic paths, then apply extract-method refactoring to pull the deepest nested blocks (nesting depth 5) into named helper functions — each helper can be tested and reasoned about in isolation, cutting both CC and ND in the parent.
